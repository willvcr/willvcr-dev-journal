# Creating a Bilingual Web Design Brief

**Date:** 2026-07-26  
**Topic:** Web Design, Client Discovery, and Project Documentation  
**Status:** Completed

## What I Worked On

Today, I created a reusable Web Design Brief in both English and Spanish.

The purpose of these documents is to collect the information required before planning, estimating, designing, or developing a website for a client.

Both versions include questions about:

- The business and its services
- Website goals
- Target audience
- Required pages
- Features and integrations
- Content and available materials
- Visual identity and brand preferences
- Domain, hosting, and technology
- SEO, analytics, and marketing
- Budget, timeline, and approval process

I also organized both Word documents inside the `resources` section of this repository so they can be reused for future website projects.

## What I Learned

- A Web Design Brief helps define a website project before development begins.
- A brief collects both business information and technical requirements.
- Clear questions help prevent misunderstandings, missing content, and unexpected changes.
- The English and Spanish versions should follow the same structure and collect equivalent information.
- Reusable resources should be stored separately from journal entries.
- Client passwords and sensitive credentials should never be requested or stored in a public document.
- Completed client briefs should not be published in a public GitHub repository.
- Clear documentation is an important part of a professional web development workflow.

## Challenges

One challenge was understanding the difference between a Web Design Brief and other client documents.

A brief focuses primarily on understanding the business, project objectives, audience, content, design preferences, website scope, and technical requirements.

A broader client onboarding questionnaire may also include contracts, payment information, communication preferences, and administrative procedures.

Another challenge was deciding how to organize the documents in GitHub without mixing reusable resources with learning-journal entries.

## Solution

I created two matching and reusable documents:

- An English Web Design Brief
- A Spanish Web Design Brief

I stored the blank templates in the `resources` directory and documented the work separately in this journal entry.

This structure keeps the repository organized:

```text
willvcr-dev-journal/
├── entries/
│   └── 2026/
│       └── 07/
│           └── 2026-07-26-creating-a-bilingual-web-design-brief.md
├── resources/
│   ├── README.md
│   ├── Web_Design_Brief_English.docx
│   └── Brief_de_Diseno_Web_Espanol.docx
└── templates/
    └── entry-template.md
```


    The public repository contains only blank reusable templates. Any document completed by a real client must remain private because it may contain confidential business information.
